# wechatagent

本地优先的个人微信关系记忆：归档电脑端已同步到本机的聊天数据，提供原文可追溯搜索、联系人关系工作台与后续的待办/摘要能力。

## 当前状态

- 已进入正式开发：亮蓝 UI Demo 已验收，正式前后端骨架已建立。
- 数据范围：仅用户本人电脑端微信已经同步到本机的数据。
- 隐私边界：本地 API 仅监听 `127.0.0.1`；真实聊天内容不上传、不写运行日志、不提交 Git。
- 真实采集：开发和自动化测试使用合成连接器；真实连接器仍保持 `connector_missing`。多账号显式选择安全闸门、合成适配器协议和前端安全交互均已覆盖，真实采集 Go/No-Go 尚未获执行授权，未读取或导入真实聊天记录。

## 项目结构

- `prototypes/ui-demo/`：已验收的视觉与交互基线（React + Vite）。
- `backend/`：FastAPI、SQLite、SQLAlchemy、Alembic、FTS5、标准采集适配器与自动化测试。
- `frontend/`：React + TypeScript 正式界面，已接入数据源状态、同步与最近运行记录、联系人档案、聊天证据、独立全局原文搜索、只读本地时间线、用户手动标签、消息上下文、用户确认事实、事实变更历史、用户手动知识卡与待办事项。
- `docs/`：PRD、开发计划、技术边界和 UI 规范。

## 本地开发验证

```powershell
# 后端：合成数据模式（默认）
Set-Location backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765

# 前端：另开一个终端
Set-Location frontend
npm install
npm run dev
```

首次启动后，在前端点击“首次归档”即可导入合成数据；这不会访问微信。首次归档成功后，默认每 5 分钟会为该合成账号执行一次幂等增量同步，页面会显示调度状态和最近同步结果。自动调度不会在真实连接器模式下运行。“全局搜索”默认在当前账号全部已归档消息中查询，可选按联系人、消息类型、日期和“仅含附件”筛选；结果可打开消息上下文或作为用户手动事实、待办的证据。只读“时间线”按发生时间聚合已归档原文、联系人资料/事实历史、本地知识卡和手动待办操作；用户可按类型或当前联系人收窄，证据项可继续打开原文上下文。“标签管理”只允许用户手动创建、编辑、删除标签，并显式关联同账号联系人、事实、知识卡或待办；同步不会自动创建或修改标签。附件只显示文件名、类型与大小，绝不返回本地路径或读取文件内容。随后可在“聊天证据”查看联系人私聊与该联系人在已归档群聊中的发言，并从证据或关键词搜索结果打开消息上下文。关系总览中的“联系人档案”可维护本地备注、确认实名、公司和角色；这些用户覆盖值不会被同步覆盖，也不代表聊天自动结论。已确认事实和本地知识卡均只由用户手动创建或确认，可选关联已归档原文证据；每次创建、编辑和删除都保留本地历史快照，不代表聊天自动结论。待办事项同样只由用户手动创建，可选关联已归档原文并保留创建、更新、完成和删除的本地快照；不会从聊天自动生成。数据库迁移会在临时 SQLite 数据库中自动验证可从空库升级到当前版本。

“本地数据管理”中的“备份前清单”仅显示当前明确选择账号的 SQLite 完整性与聚合数量，不生成文件、不显示路径或聊天原文。删除本地数据需要先准备一个十分钟有效的删除请求，再输入显示的精确确认短语；删除范围仅为该账号的本地归档和用户手动记录，数据源检测不受影响，且该操作不可恢复。

本地数据管理还会比较原始消息数量和 FTS5(trigram) 索引条目；若索引不完整，用户可显式重建当前账号的全文索引。重建只重写本地索引，不会修改原始消息、调用同步或接触微信。

首次打开时，用户必须确认本地处理边界后才会发起数据源探测；该确认只保存本机安全模式状态，不授权真实采集，也不启用 AI 或云端处理。设置页面会持续显示这些限制。

验证真实采集前，只能运行后端与前端的合成测试。不得安装或执行 `wx-cli`，也不得读取、解密、导入或上传真实微信聊天数据，直到用户明确授予 Go/No-Go 执行授权。

## 重要边界

个人微信没有面向普通第三方的稳定全量历史 API。采集层必须保持为可替换、只读的适配器；产品不承诺手机端全量历史、零遗漏或永久兼容所有微信版本。
